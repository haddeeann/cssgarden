overflow Is a Model, Not a Switch

Every overflow value except visible changes how a box participates in layout — not just what users can see. Here is what each value actually does, and why picking the wrong one causes bugs.

Try it — change overflow on the container, watch content clip or scroll

A floated image escaping its container, a decorative banner bleeding into the next section, a sidebar that refuses to scroll — these are all overflow problems, but they rarely share the same fix. overflow is not a four-option switch. It is a model that governs whether a box becomes a scroll container, whether it establishes a new block formatting context, and whether content is merely hidden from view or actually removed from layout influence. Picking the wrong value is one of the most common roots of mysterious CSS layout bugs.

Start from visible — the baseline that does nothing

overflow: visible is the default, which is why tutorials rarely mention it. But it is the conceptual anchor for everything else, and it is worth naming explicitly: visible is the only value that does not create a scroll container and does not establish a block formatting context. Content paints wherever it needs to, even if that means spilling outside the box's border edge. The box's size is determined by its content in normal flow, and its relationship to neighboring boxes is unchanged.

Every other value — hidden, scroll, auto, and the newer clip — is a departure from this baseline. Understanding what each departure costs, not just what it gains, is the whole game.

The four classic values

hidden

overflow: hidden clips content at the box's padding edge. Content beyond that boundary is invisible and cannot be scrolled to — gone from the user's perspective, but not from the layout. The overflowing content still exists in the DOM, still occupies space in its own formatting context, and still participates in focus order and find-in-page. Clipping the paint does not remove the element.

The bigger surprise is what hidden does to the box itself: it establishes a new block formatting context. Floated children are contained, and margin collapsing between the box and its children is suppressed. Developers who reach for overflow: hidden to clip a decorative image are quietly opting into float containment and margin-collapsing suppression — layout behaviors that have nothing to do with their actual intent.

/* Clips the image AND creates a new BFC.
   Floated children are now contained. */
.card {
  overflow: hidden;
}

scroll

overflow: scroll creates a scroll container and a block formatting context, but always reserves space for scrollbars — even when there is nothing to scroll. On operating systems with persistent scrollbars (most Windows configurations), a scrollbar gutter appears regardless of whether content overflows. That reserved space can cause layout shift when content is added or removed dynamically, because the available width inside the container changes. The modern answer is the scrollbar-gutter property, which reserves gutter space independently of whether a scrollbar is present.

/* Always shows scrollbar gutters; content area is stable. */
.feed {
  overflow: auto;
  scrollbar-gutter: stable;
}

auto

overflow: auto creates a scroll container and a block formatting context, just like scroll, but scrollbars only appear when content actually overflows. For most scrollable regions it is the right default. The caveat is the same as with scroll: when a scrollbar appears it consumes space from the content area, which can reflow content. For interfaces where that reflow is unacceptable, pair it with scrollbar-gutter: stable.

clip

overflow: clip is the surgical option most tutorials have not caught up to yet. Like hidden, it clips content at the box's padding edge — but unlike hidden, it does not create a scroll container and does not establish a block formatting context. It is a pure paint operation. Floats are not contained. Margin collapsing is not suppressed. When you want to clip a decorative overflow without side effects, clip is the right tool.

Browser support is solid across modern browsers, though clip is absent from Internet Explorer. Authors targeting legacy environments must use hidden and accept the BFC side effects.

/* Clips paint only. No BFC, no scroll container. */
.hero-image-wrapper {
  overflow: clip;
}

The axis-coupling rule

overflow is shorthand for overflow-x and overflow-y. overflow: hidden sets both axes to hidden. Two values — overflow: hidden auto — apply the first to the x axis and the second to the y axis. So far, straightforward.

The rule that catches developers off guard: if you set one axis to hidden, scroll, or auto, and explicitly set the other axis to visible, the browser silently overrides that visible to auto. This is specified behavior, not a bug. A scroll container cannot simultaneously scroll on one axis and allow content to paint freely outside its bounds on the other — the rendering model does not permit it, so the browser resolves the conflict by promoting visible to auto.

The practical consequence is that this code does not do what it appears to say:

/* Intended: clip horizontal overflow, allow vertical overflow.
   Actual: overflow-y computes as auto, not visible. */
.slider {
  overflow-x: hidden;
  overflow-y: visible;
}

If you genuinely need to clip one axis without affecting the other, overflow: clip is the fix. Because clip does not create a scroll container, it does not trigger the axis-coupling rule:

/* This works as intended. */
.slider {
  overflow-x: clip;    /* clips paint on x, no scroll container */
  overflow-y: visible; /* genuinely visible — not overridden */
}

The companion property overflow-clip-margin lets you define how far outside the box clipped content may paint before being cut — useful when a box-shadow or outline should remain visible beyond the element's edge while the content itself is clipped. Note that overflow-clip-margin only takes effect when both axes are set to clip.

Choosing the right value

Start by asking what you actually want the box to do:

  • Let content paint freely, no containment needed: overflow: visible. This is the default — do nothing.
  • Clip decorative overflow without affecting layout: overflow: clip. No BFC, no scroll container, no axis-coupling risk.
  • Clip content and also need float containment or margin-collapsing suppression: overflow: hidden. You are getting a BFC intentionally.
  • Create a scrollable region, show scrollbars only when needed: overflow: auto. Pair with scrollbar-gutter: stable if layout stability matters.
  • Create a scrollable region with permanently reserved scrollbar space: overflow: scroll. Useful when content will always overflow and you want no reflow when it does.

One more pattern worth naming: the three-property recipe for truncating text with an ellipsis — overflow: hidden; white-space: nowrap; text-overflow: ellipsis — is widely copy-pasted without explanation. All three are load-bearing. text-overflow only applies when overflow is actually occurring (overflow: hidden or clip), and white-space: nowrap is what forces the text to overflow in the first place rather than wrapping to a new line. Remove any one of the three and the ellipsis disappears.

/* All three are load-bearing. */
.label {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

The overflow model is one of those corners of CSS where the default is invisible — content just goes where it goes — and the moment you intervene, you are doing more than you might realize. Naming the scroll container, the block formatting context, and the axis-coupling rule gives you the vocabulary to read what your CSS is actually doing, not just what you intended it to do.
